### 📊 회귀 모델 성능 지표 설명

- **Model (모델)**사용된 알고리즘 이름입니다. 예: 선형회귀, KNN, Lasso 등.
- **MAE (Mean Absolute Error, 평균 절대 오차)**

  - 예측값과 실제값의 차이를 절댓값으로 계산한 뒤 평균낸 값.
  - 공식: \(\text{MAE} = \frac{1}{n}\sum |y_i - \hat{y}_i|\)
  - 단위: 목표 변수와 동일. 값이 작을수록 좋음.
  - 특징: 큰 오차를 특별히 더 크게 벌하지 않고, 직관적으로 "평균적으로 얼마나 틀렸는가"를 보여줌.
- **MSE (Mean Squared Error, 평균 제곱 오차)**

  - 예측값과 실제값의 차이를 제곱해 평균낸 값.
  - 공식: \(\text{MSE} = \frac{1}{n}\sum (y_i - \hat{y}_i)^2\)
  - 큰 오차에 더 큰 패널티를 줌. 값이 작을수록 좋음.
  - 단위: 목표 변수의 제곱 단위라 직관성은 떨어짐.
- **RMSE (Root Mean Squared Error, 평균 제곱근 오차)**

  - MSE의 제곱근.
  - 공식: \(\text{RMSE} = \sqrt{\text{MSE}}\)
  - 단위가 목표 변수와 같아 해석이 쉬움. 값이 작을수록 좋음.
  - 큰 오차에 민감.
- **R2 (Coefficient of Determination, 결정계수)**

  - 모델이 데이터의 분산을 얼마나 설명하는지 나타냄.
  - 공식: \(\text{R}^2 = 1 - \frac{\sum (y_i - \hat{y}_i)^2}{\sum (y_i - \bar{y})^2}\)
  - 범위: 보통 -∞ ~ 1.
    - 1: 완벽한 설명력
    - 0: 평균값 예측과 동일
    - 음수: 평균값 예측보다 못함
  - 높을수록 좋음.
- **RMSLE (Root Mean Squared Logarithmic Error, 평균 제곱근 로그 오차)**

  - 실제값과 예측값을 로그 변환한 뒤 RMSE 계산.
  - 공식: \(\sqrt{\frac{1}{n}\sum (\ln(1+\hat{y}_i) - \ln(1+y_i))^2}\)
  - 상대적 차이를 강조하며, 값이 큰 경우에도 완화된 평가를 제공.
  - 값이 작을수록 좋음.
  - 단, 음수나 0 값이 많으면 사용하기 어려움.
- **MAPE (Mean Absolute Percentage Error, 평균 절대 백분율 오차)**

  - 실제값 대비 예측값의 오차를 백분율로 환산해 평균낸 값.
  - 공식: \(\text{MAPE} = \frac{100}{n}\sum \left|\frac{y_i - \hat{y}_i}{y_i}\right|\)
  - 직관적으로 "평균적으로 몇 % 틀렸는가"를 보여줌.
  - 값이 작을수록 좋음.
  - 단, 실제값이 0에 가까우면 값이 폭발적으로 커질 수 있음.
- **TT (Sec, Training Time)**

  - 모델 학습에 걸린 시간(초 단위).
  - 값이 작을수록 빠른 학습.
  - 데이터 크기, 알고리즘 복잡도, 하드웨어 성능에 따라 달라짐.

---

👉 요약하면:

- **MAE/RMSE** → 평균적으로 얼마나 틀렸는지 (절대/제곱 기준).
- **R2** → 모델이 데이터를 얼마나 잘 설명하는지.
- **MAPE/RMSLE** → 상대적 오차를 평가.
- **TT** → 학습 속도.

## 📌 회귀 모델 선택 기준 정리

### 1. **절대 오차 중심 (MAE, RMSE)**

- **MAE**: 평균적으로 얼마나 틀렸는지 직관적으로 보여줌.→ **데이터에 이상치(Outlier)가 많을 때** 적합.
- **RMSE**: 큰 오차에 더 민감.
  → **큰 오차를 줄이는 것이 중요한 경우**(예: 의료, 금융 예측) 적합.

---

### 2. **설명력 중심 (R²)**

- 모델이 데이터를 얼마나 잘 설명하는지 확인 가능.
- **R²가 높을수록 좋은 모델**.
- 단, 데이터 분산이 적거나 비선형 패턴이 강하면 R²만으로 판단하기 어려움.
  → **모델 비교 시 가장 많이 쓰이는 기준**.

---

### 3. **상대적 오차 중심 (MAPE, RMSLE)**

- **MAPE**: "평균적으로 몇 % 틀렸는가"를 보여줌.→ **비즈니스/재무 데이터**처럼 상대적 정확도가 중요한 경우 적합.
- **RMSLE**: 로그 변환으로 큰 값의 영향 완화.
  → **성장률, 매출, 수요 예측**처럼 값의 크기가 크게 변하는 경우 유용.

---

### 4. **학습 시간 (TT)**

- 모델을 반복적으로 학습하거나 대규모 데이터에서 사용할 때 중요.
- **빠른 프로토타이핑**이나 **실시간 예측 서비스**에서는 학습 시간이 짧은 모델 선호.
- 하지만 최종 성능이 더 중요하다면 학습 시간이 길어도 성능 좋은 모델을 선택.

---

## ✅ 결론

- **데이터에 이상치가 많다** → MAE 중심
- **큰 오차를 줄이는 게 중요하다** → RMSE 중심
- **모델 설명력을 보고 싶다** → R² 중심
- **상대적 정확도가 중요하다** → MAPE / RMSLE 중심
- **실시간/대규모 서비스** → TT(학습 시간) 고려

## 📌 Mercari Price Suggestion 데이터 특성

- **타겟 변수:** 상품 가격 (연속형, 단위는 달러)
- **분포:** 가격이 **0에 가까운 값부터 수천 달러까지** 매우 넓게 퍼져 있음 → **심하게 비대칭(스큐)**
- **비즈니스 목표:** 예측값이 실제 가격과 **상대적으로 얼마나 차이가 나는지**가 중요
  (예: 10달러 상품을 20달러로 예측하는 것과 1000달러 상품을 1010달러로 예측하는 것은 절대 오차는 비슷해도 의미가 다름)

## 📊 적합한 지표

- **RMSLE (Root Mean Squared Logarithmic Error)**
  - Mercari 대회 공식 평가 지표.
  - 로그 변환을 통해 **상대적 오차**를 평가 → 작은 값일수록 좋음.
  - 고가 상품의 큰 절대 오차가 지나치게 모델을 망치지 않도록 완화.
  - 저가 상품의 상대적 오차를 더 중요하게 반영.
  - 공식:
    \[
    RMSLE = \sqrt{\frac{1}{n}\sum_{i=1}^{n} \left(\ln(1+\hat{y}_i) - \ln(1+y_i)\right)^2}
    \]

---

## ✅ 결론

- Mercari Price Suggestion Challenge에서는 **RMSLE**가 가장 적합한 지표입니다.
- 이유: 가격 데이터가 **스케일이 크고 비대칭적**이기 때문에, 단순 MAE/RMSE보다 **상대적 예측 정확도**를 평가하는 RMSLE가 더 현실적이고 공정합니다.
- 실제 캐글 대회에서도 **RMSLE**가 공식 평가 기준으로 사용되었습니다.

**핵심 요약:**  
Mercari Price Suggestion 데이터는 크고 불균형적이라 메모리 문제가 자주 발생합니다. 가장 좋은 접근은 **효율적인 샘플링(undersampling + feature engineering 최적화)**을 병행하는 것이고, 실제 캐글 상위권 팀들도 단순 undersampling보다는 **텍스트/이미지 임베딩 + 앙상블 모델**을 활용했습니다. 대회 공식 평가 지표는 **RMSLE**였으며, 1~3위 팀 모두 **LightGBM, Ridge/Linear 모델, 신경망 앙상블**을 조합했습니다.

---

## 📌 메모리 문제 해결을 위한 샘플링 전략
- **Undersampling 추천 방법**
  - **Stratified undersampling:** 가격 구간별로 층화해 균형 있게 샘플링 → 저가/고가 모두 반영.
  - **Random undersampling:** 단순히 데이터 일부를 무작위로 줄임 → 빠르지만 정보 손실 위험.
  - **Hybrid 방법:** undersampling으로 데이터 크기를 줄이고, 이후 **feature hashing / 차원 축소(PCA, TruncatedSVD)**로 메모리 최적화.
- **실무 팁**
  - 텍스트 피처는 **TF-IDF 대신 hashing vectorizer** 사용 → 메모리 절약.
  - 이미지 피처는 미리 임베딩 후 저장 → 학습 시 불필요한 중복 계산 방지.
  - PyCaret 실행 시 `n_jobs`를 제한하고, 데이터셋을 **chunk 단위**로 나눠 학습.
