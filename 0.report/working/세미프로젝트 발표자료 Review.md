## 4. Mercari Price Suggestion

### 1조

* **오차 해석 (로그 변환)**

  * 오차에 로그를 적용하면 **Proportional(비율) 오차**로 해석 가능
  * RMSLE 사용 시, 예측값은 실제 가격 대비 평균 약 **45% 수준의 비율 오차**를 가짐
  * 단순히 로그 변환 자체보다 **어떤 오차값에 로그를 적용하는지**가 중요

* **한계점 및 개선 방향**

  * 텍스트 데이터 품질 저하
  * 실시간 시장 변화 반영의 어려움
  * 희소 데이터(Sparsity) 구조적 한계
  * 이미지 데이터 미활용

* **LLM + Agent 활용 제안**

  * Agent + LLM으로 기존 한계 극복 가능
  * HuggingFace 기반 Large Language Model 사용 시

    * 한글 최적화 측면에서 ChatGPT, Gemini보다 더 나은 결과 가능

* **멀티모달 확장**

  * 이미지 데이터 처리 → CNN
  * 이미지를 텍스트로 변환 후 LLM 학습 → 멀티모달의 시작점
  * 이미지 내 텍스트 인식(OCR) → 이미지 + 텍스트 동시 활용
  * 실습 예정

* **데이터 확장 아이디어**

  * 바이너리 데이터 → 텍스트 변환 가능
  * 음성 데이터 → 텍스트 변환 후 학습
  * 텍스트 / 이미지 / 영상 → 텍스트화 후 멀티모달 적용

* **실무 활용 예시**

  * 자동화 파이프라인 구축 → 기업 실무에서 매우 유용
  * PDF 이미지 처리 라이브러리 활용
  * 회의록 자동 생성 (녹음 → 음성 인식 → 텍스트)
  * 음성 추출 가능
  * 이미지 분석 (이미지 내용 분류 및 해석)

## 7. Palantir Ontology & Knowledge Graph 정리

### 🧩 Palantir Ontology (온톨리지)

**정의**

* 조직의 데이터와 비즈니스 개념을 의미론적으로 구조화한 계층적 모델

**특징**

* 비즈니스 운영 모델링

  * 데이터베이스를 넘어 조직의 프로세스, 자산, 사람, 이벤트를 디지털 트윈 형태로 표현
* 관계 및 의존성 매핑

  * 자원 배분, 공급망, 금융 거래 등 관계를 명확히 표현하여 의사결정 지원
* 확장성

  * 신규 데이터 소스 추가 시 기존 구조와 자연스럽게 연결

---

### 🌐 Knowledge Graph (지식 그래프)

**정의**

* 노드(개체)와 엣지(관계)로 구성된 그래프 구조의 데이터 모델

**구성 요소**

* 노드: 사람, 조직, 장소, 이벤트, 제품 등
* 엣지: 소속, 발생, 연결 관계
* 속성: 이름, 날짜, 위치, 직책 등

**활용 사례**

* 사기 탐지: 금융 거래 관계 분석을 통한 이상 패턴 탐지
* 예측 분석: 공급망, 자원 흐름 시뮬레이션
* 데이터 통합: 이질적 데이터의 의미론적 통합 및 실시간 분석

---

### 🚀 확장 방식

* Layered 구조: 단순 데이터 연결을 넘어 비즈니스 로직까지 반영
* Semantic Web 기반 확장
* Neo4j와 유사한 그래프 DB 기능 제공

---

### ⚠️ 고려 사항

* 초기 구축 복잡성 → 도메인 지식 필수
* 높은 도입 및 운영 비용
* 데이터 품질 의존성 높음

---

## 요약

* Ontology는 **데이터와 비즈니스 개념을 의미적으로 모델링하는 기반**
* Knowledge Graph는 **복잡한 관계를 실시간으로 분석·확장하는 도구**
* 두 기술의 결합을 통해 데이터는 단순 저장을 넘어 **운영 자산**으로 활용 가능
